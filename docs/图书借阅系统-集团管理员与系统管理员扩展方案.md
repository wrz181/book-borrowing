# 图书借阅管理系统 —— 「集团管理员 / 系统管理员 / 外系统集成」扩展方案

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 图书借阅管理系统（J2EE 期末项目 P01-F2-R03） |
| 现有技术栈 | Spring Boot 3.2.5 + MyBatis 3.0.3 + MySQL 8 + JWT(jjwt) + BCrypt / Vue 3 + Element Plus + Vite + Pinia |
| JDK | 21 |
| 本文档目的 | 在对现有 CRUD 系统做扩展前，明确需求边界、技术选型、数据模型与分期计划，供评审确认 |

---

## 一、背景与现状

现有系统是一个前后端分离的图书借阅单体应用，已具备：

- 三张核心业务表：`book_category`（分类）、`book`（图书）、`borrow_record`（借阅记录），外加 `sys_user`（登录用户）；
- 基础 CRUD、MyBatis 动态条件查询、多表关联查询；
- 个人指定功能 F2：图书详情一对多关联全部借阅记录；
- 个人业务规则 R03：同一借阅人 + 同一图书 + 同一借阅日不得重复借阅，配套库存联动；
- JWT 登录 + 拦截器鉴权（除登录外所有 `/api/**` 需携带 token）；
- 已完成但尚未提交的改造：全表**逻辑删除**（`is_deleted`）。

**现状缺口**：没有角色与权限体系、没有第三方（外系统）集成能力、没有管理控制台。

---

## 二、需求目标

对标致远 A8 的「集团管理员 + 系统管理员 + 外系统集成（SSO / 待办 / 消息）」，在本项目内做一套**仿真实现**。左侧菜单扩展为四段：

```
图书借阅      （现有：图书 / 分类 / 借阅记录，并新增「图书采购」）
集团管理员    （新增，位于「系统管理员」左侧）
   ├ 账号与权限        新增普通人员账号 + 给角色配置权限
   ├ 单点登录 / 应用集成 配置第三方应用（应用名+地址+密钥）→ 侧边栏出现该应用栏目 → 点击 SSO 跳转「类ERP平台」
   ├ 待办中心          ERP 侧完成表单 → 本系统生成待办
   └ 消息中心          集成方向本系统推送消息提醒
系统管理员    （新增：日志类型设置 / 内存监控 / JS 缓存清理）
```

角色行为差异：

- **普通人员账号**：登录后**只能发起借阅表单**与查看基础数据；**没有**新增/删除图书、向 ERP 发送表单、采购、进入管理台的权限。
- **集团管理员**：管理账号、配置角色权限、配置外部应用、处理待办与消息。
- **系统管理员**：日志级别、内存监控、缓存清理。

## 三、技术选型（已确认）

| 决策点 | 选型 | 理由 |
| --- | --- | --- |
| 「类ERP平台」形态 | **同工程内独立模块**（后端 `/erp/**` + 前端独立布局页），用 SSO ticket 模拟跨系统跳转 | 只跑一个服务，演示方便；相比独立第二工程，工作量与部署复杂度显著降低 |
| 权限模型 | **RBAC**：角色 + 权限点可配（`sys_role` / `sys_permission` / `sys_role_permission`） | 满足"在集团管理员里可以给权限"的可配置要求 |
| 日志类型设置 | **真接 Logback**（运行时修改指定模块日志级别，立即生效）+ 内存环形缓冲日志查看 | 贴近致远系统管理员的真实行为 |
| 数据库 | 沿用单库 `bookborrowing`，新增表 + 增量脚本 | 改动可控，已有数据不丢失 |
| 后端鉴权风格 | 自定义 `@RequirePermission` 注解 + 拦截器（不引入完整 Spring Security） | 与现有工程风格一致（现仅用 spring-security-crypto） |
| 交付节奏 | **先做阶段一 + 二**（权限地基 → 集团管理员），再做阶段三、四 | 先立地基，避免返工 |

## 五、阶段一：权限地基（RBAC）

### 5.1 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sys_role` | `role_code`(SYS_ADMIN / GROUP_ADMIN / NORMAL)、`role_name`、`is_builtin`、`is_deleted` | 角色字典 |
| `sys_permission` | `perm_code`、`perm_name`、`perm_type`(MENU/ACTION)、`parent_code`、`sort_no` | 权限点字典 |
| `sys_role_permission` | `role_id`、`perm_code`（唯一约束） | 角色↔权限关联 |
| `sys_user`（加列） | `role_id`（默认指向 NORMAL） | 账号角色 |

### 5.2 后端鉴权

- 新增注解 `@RequirePermission("book:add")`；新增 `PermissionInterceptor`，在 `JwtInterceptor` 之后注册，从 `currentUserId` 查角色权限并校验。
- **权限为后端强校验**，前端隐藏按钮只是体验层，不作为安全边界。
- 权限结果使用内存缓存；角色权限变更时主动失效。
- 登录接口 `POST /api/auth/login` 与 `GET /api/auth/info` 返回值扩展为：
  ```json
  {
    "token": "…",
    "userInfo": { "id": 1, "username": "admin", "nickname": "系统管理员", "roleCode": "SYS_ADMIN", "roleName": "系统管理员" },
    "permissions": ["book:view", "book:add", "group:user"]
  }
  ```

### 5.3 前端

- `stores/user.js` 增加 `permissions`；
- 新增 `v-permission="'book:add'"` 指令控制按钮显隐；
- 路由 `meta.perm` + 全局守卫做访问拦截；
- 侧边栏按权限渲染菜单项。

### 5.4 权限点清单（初版，可调整）

| 分类 | 权限点 |
| --- | --- |
| 图书 | `book:view` `book:add` `book:edit` `book:delete` |
| 分类 | `category:view` `category:manage` |
| 借阅 | `borrow:view` `borrow:apply` `borrow:return` `borrow:manage` |
| 采购 | `purchase:view` `purchase:manage` |
| 集团管理 | `group:user` `group:role` `group:app` `group:todo` `group:message` |
| 系统管理 | `system:log` `system:monitor` `system:cache` |

> `group:app`（应用集成配置）是**集成应用的唯一入口权限**：侧边栏「集成应用」动态栏目按它渲染，领票接口 `GET /api/sso/ticket` 也按它做 `@RequirePermission` 校验。因此集成应用的**配置与进入均为集团管理员职责**，`SYS_ADMIN`、`NORMAL` 既看不到栏目也领不到票（403）。

### 5.5 内置角色默认权限

| 角色 | 默认权限 | 说明 |
| --- | --- | --- |
| `NORMAL`（普通人员） | `book:view` `category:view` `borrow:view` `borrow:apply` `borrow:return` | 只能查看 + 发起借阅 + 归还，无 add/delete/采购/管理台 |
| `GROUP_ADMIN`（集团管理员） | 业务全量 + `group:*` | 管理账号、角色权限、应用、待办、消息 |
| `SYS_ADMIN`（系统管理员） | 业务只读（`book:view` `category:view` `borrow:view`）+ `system:*` | 日志、内存、缓存；不参与业务增删改，职责与集团管理员分离 |

> **待确认（默认判断，评审时可改）**
> 1. 现有 `admin` 账号角色：建议为 **系统管理员(SYS_ADMIN)**，另初始化 `groupadmin` = **集团管理员(GROUP_ADMIN)**。
> 2. 集团管理员可配置范围：建议**只能配置 `NORMAL` 角色**，两个内置管理员角色锁定不可改（防止自我提权/互相提权）。
> 3. 普通人员是否可归还自己发起的借阅：建议**授予 `borrow:return`**。

## 六、阶段二：集团管理员控制台

### 6.1 数据模型

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `integration_app` | `app_name`、`app_url`、`sso_secret`、`enabled` | 单点登录应用配置 |
| `integration_form` | `app_id`、`title`、`form_type`、`content`(JSON)、`status`(0待处理/1已处理)、`sender_id`、`handle_time` | 下发给 ERP 的表单 |
| `todo_item` | `title`、`biz_type`、`biz_id`、`receiver_id`、`status`(0待办/1已办)、`done_time` | 待办事项 |
| `message_item` | `title`、`content`、`receiver_id`、`read_flag` | 消息提醒 |

### 6.2 接口

| 方法 | 路径 | 所需权限 | 说明 |
| --- | --- | --- | --- |
| GET/POST/PUT/DELETE | `/api/admin/users` | `group:user` | 账号 CRUD、启用/禁用、重置密码（逻辑删除） |
| GET | `/api/admin/roles` | `group:role` | 角色列表（含权限） |
| PUT | `/api/admin/roles/{id}/permissions` | `group:role` | 角色权限勾选 |
| GET/POST/PUT/DELETE | `/api/admin/apps` | `group:app` | 单点登录应用配置 |
| GET | `/api/todos/page` | `group:todo` | 待办分页 |
| PUT | `/api/todos/{id}/done` | `group:todo` | 办理待办 |
| GET | `/api/messages/page` | `group:message` | 消息分页（含未读数） |
| PUT | `/api/messages/read` | `group:message` | 标记已读 / 全部已读 |
| GET | `/api/sso/ticket?appId=` | JWT + `group:app` | 生成 SSO ticket，前端跳转 `app_url?appId=&ticket=`（阶段三接入类ERP平台校验）；**仅集团管理员可领票**，`SYS_ADMIN` 与 `NORMAL` 返回 HTTP 403 |

### 6.3 页面

- 侧边栏新增分组「**集团管理员**」：账号管理 / 角色权限 / 应用集成 / 待办中心 / 消息中心；
- `integration_app` 中启用的应用以**动态栏目**形式出现在侧边栏，点击走 SSO 跳转；
- 顶部/菜单显示**待办、消息未读徽标**；
- 「系统管理员」三功能（日志类型设置/内存监控/JS缓存清理）**已实现**；2026-10-19 起维护类功能统一迁入独立后台 `/backend/**`（见文末「九、OA 三员与后台扩展」）。

## 七、阶段三：类ERP平台（独立端口）+ 集成闭环 + 图书采购

- 类ERP平台：**独立进程 + 独立端口 5174**（`erp-frontend/`），零依赖 Node 静态服务 + `/api/**` 反向代理；见第十五节。
- 后端 `/api/open/**`：**不走 JWT**，以 SSO ticket 校验身份（模拟第三方系统会话）。
- 集成闭环：本系统下发 `integration_form` → ERP 侧办理并提交 → 回调本系统 → 自动生成 `todo_item` + `message_item`。
- `integration_app` 配置的应用名 → 侧边栏栏目 → 点击 SSO 跳转到 ERP 页面（`?appId=&ticket=`）。
- 图书采购：新增 `book_purchase`（图书名称/作者/ISBN/出版社/分类/单价/数量/状态/申请人与各节点时间），**入库后按 ISBN（优先）或名称匹配已有图书增加库存，未匹配则新增图书**，权限点 `purchase:view` / `purchase:manage`；见第十四节。

### 13.2 关键实现说明

- **权限强校验**：`PermissionInterceptor` 校验方法级/类级 `@RequirePermission`，无权限返回 **HTTP 403**；权限带 `PermissionCache` 内存缓存，角色权限或账号角色变更时失效。
- **登录返回**：`POST /api/auth/login` 返回 `token + userInfo(含 roleCode/roleName) + permissions[]`；`GET /api/auth/info` 同步返回。
- **内置角色保护**：`SYS_ADMIN`、`GROUP_ADMIN` 为内置角色，权限锁定不可改；仅 `NORMAL` 可在页面上配置。
- **单点登录 ticket**：`Base64(appId:userId:expire).MD5签名`，密钥取该应用的 `sso_secret`，有效期 5 分钟。
- **待办/消息集成**：外系统回调 `POST /api/open/todo`、`POST /api/open/message`（走 `X-App-Id` + `X-App-Secret`，不经 JWT）；类ERP回传表单 `POST /api/open/form/submit` 校验 ticket 后落库并生成待办 + 消息。
- **应用停用全通道封堵**：`enabled=0` 时票据下发（`/api/sso/ticket`）、App-Key 推送（`/api/open/todo`、`/api/open/message`）与票据校验（`/api/open/sso/validate`）统一返回「应用已停用」，左侧「集成应用」栏目同步不渲染该应用。
- **类ERP平台独立端口**：`erp-frontend/`（零依赖 Node 静态服务 + `/api/**` 反向代理）监听 **5174**，与主系统前端 5173、后端 8080 相互独立；从主系统左侧「集成应用」栏目点击即以 `?appId=&ticket=` 单点登录打开。
- **图书采购模块**：`book_purchase` 表 + 完整状态机（0 草稿 / 1 已提交 / 2 已入库 / 9 已取消），提交可下发集成表单给外部应用，外部回执后方可入库；入库按 **ISBN 优先、否则图书名称** 匹配已有图书增加库存，未匹配则新增图书。
- **日志类型设置**：`LogStore` 以 Logback `AppenderBase` 挂到 Root Logger，环形缓冲 1000 条；按模块运行时 `setLevel` 真改 Logback 级别，日志列表按「级别 ≥ 所选级别」过滤。
- **内存监控**：基于 `ManagementFactory` 采集堆/非堆、内存池、GC、线程与运行时信息。

## 十四、图书采购业务模块（完整闭环）

### 14.1 数据模型

新增表 `book_purchase`（`sql/upgrade-purchase.sql`，同步纳入 `sql/bookborrowing.sql`）：

| 字段 | 说明 |
| --- | --- |
| `purchase_no` | 采购单号（唯一），格式 `CG + yyyyMMddHHmmss + 3 位随机` |
| `book_name` / `author` / `isbn` / `publisher` / `category_id` | 图书信息（`category_id` 必填，入库归入该分类） |
| `quantity` / `unit_price` / `total_price` | 数量 / 单价 / 总价（总价 = 数量 × 单价，后端计算） |
| `applicant_id` / `applicant_name` | 申请人（取当前登录用户） |
| `app_id` / `integration_form_id` | 下发的集成应用与生成的集成表单 |
| `status` | 0 草稿 / 1 已提交 / 2 已入库 / 9 已取消 |
| `submit_time` / `stock_in_time` / `cancel_time` | 各节点时间 |
| `stock_in_book_id` / `stock_in_remark` | 入库图书与结果说明 |

### 14.2 状态机

```text
         新增(草稿 0)
             │ 提交(可同时下发外部集成应用)
             ▼
        已提交 1 ──── 取消 ────┐
             │ 入库(需外部回执完成) │
             ▼                    ▼
        已入库 2             已取消 9
                                  │ 删除(逻辑删除，仅 0/9 可删)
```

- 修改：仅 `0 草稿`；
- 入库：仅 `1 已提交`；若已下发外部平台，须等对方回执（集成表单 `status=1`）后方可入库；
- 取消：`0/1`；删除：`0/9`（逻辑删除）。

### 14.3 入库逻辑

1. 按 **ISBN 精确匹配**（`isbn` 非空时）未删除图书；
2. `isbn` 为空或未匹配到，则按 **图书名称精确匹配**；
3. 命中 → `book.stock += quantity`，入库说明「匹配已有图书【X】，库存 +N 册」；
4. 未命中 → 新增一条 `book`（名称/作者/ISBN/出版社/分类/单价取采购单，库存 = 数量，状态 1 在架），入库说明「未匹配到已有图书，新增图书并入库 N 册」；
5. 入库成功后向申请人发送一条消息提醒。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |

| GET | `/api/purchases/{id}` | `purchase:view` | 详情（含分类名、应用名、回执状态） |

## 十五、类ERP平台（独立端口部署）

### 15.1 定位

类ERP平台作为**真实跨系统部署**的模拟：**独立进程、独立端口 5174**，与图书借阅系统（前端 5173 / 后端 8080）完全分离，仅通过 HTTP 接口 + 单点登录票据交互。

### 15.2 工程结构

```text
erp-frontend/
├── package.json      # 仅声明启动脚本，无第三方依赖
├── server.js         # Node 内置模块：静态托管 + /api/** 反向代理到 8080
├── public/
│   ├── index.html    # 单点登录落地页 + 工作台（待办表单 / 已处理 / 发起表单）
│   ├── app.js        # 原生 JS：票据校验、办理表单、表单回传
│   └── style.css
└── README.md
```

启动：`cd erp-frontend; node server.js` → <http://localhost:5174/>

### 15.3 单点登录流程

1. 主系统侧 `GET /api/sso/ticket?appId=` 用应用 `sso_secret` 生成 `Base64(appId:userId:expire).MD5签名`（5 分钟有效）；
   该接口带 `@RequirePermission("group:app")`——集成应用的配置与进入均属集团管理员职责，
   系统管理员（SYS_ADMIN）与普通人员（NORMAL）领票返回 HTTP 403，无法向外部平台发送表单；
2. 主系统以 `window.open(app.appUrl + '?appId=&ticket=')` 打开 `http://localhost:5174/`；
3. 类ERP页面 `POST /api/open/sso/validate?ticket=` 校验票据并换取登录用户信息，展示「登录用户」——即「另一个本机端口可以登录打开」。

### 15.4 新增开放接口（`/api/open/**`，不经 JWT）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/open/sso/validate?ticket=` | 票据校验，返回 `appId/appName/userId/username/nickname` |
| GET | `/api/open/forms?ticket=&status=` | 本应用集成表单列表（默认 `status=0` 待处理） |
| POST | `/api/open/forms/{id}/handle` | 办理待处理表单 → 置为已处理 + 生成待办 + 生成消息 |
| POST | `/api/open/form/submit` | 发起并回传表单 → 生成待办 + 生成消息（原有） |

> 反向代理使类ERP前端与接口同源，避免跨域；后端 `WebMvcConfig` 亦已放开 `/api/**` 的 CORS（`allowedOriginPatterns("*")`），直接跨端口访问同样可用。

### 15.5 完整业务闭环演示路径

```text
1. groupadmin 登录主系统（5173）
2. 图书采购管理 → 新增采购单（草稿）→ 提交 → 选择「图书采购ERP」下发
3. 左侧「集成应用 → 图书采购ERP」单点登录打开 5174
4. 5174 工作台「待处理表单」出现该采购单 → 办理（填写处理意见）
5. 回主系统：待办中心 +1、消息中心 +1；采购单显示「已回执」
6. 采购单点「入库」→ 图书库存增加（或新增图书）
```
